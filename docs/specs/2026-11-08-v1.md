# Throne v1 spec

Date: 2026-11-08. Status: ready-for-agent. Terms are defined in `GLOSSARY.md`.

## Problem Statement

My friends and I joke about how often we go, but there's no easy, private place to log it and
compare. Notes apps and spreadsheets take too many taps, they can't show a month at a glance, and
sharing them means sending screenshots. General health apps either don't track this at all or bury
it under a dozen screens and want an account with a big company. I want something I can tap once in
the bathroom (often with bad signal), that shows how many times a Day I went on a monthly calendar,
and that I can share with up to three Friends who can see mine, react, and get a weekly Summary
with some light-hearted Awards.

## Solution

Throne is an installable web app at throne.ashershores.com. You get a Profile only through an
Invite from someone who already has one. The home screen is one big button: tap it and a Log is
saved for right now, even offline. A "details" expander lets you add Duration, Bristol type, a Note
and Flags, or change the time (up to 7 days back). The Calendar shows a month: each Day has the
count and gets darker the more Logs it has. You can view just yourself, switch to any Friend, or
see a combined grid with everyone's count in their Avatar's color. Tap a Day to see its Logs.

You add Friends by sharing your private Friend code out of band; the other person enters it and
sends a Friend request, which you accept or decline. Each Profile can have at most three Friends.
Friends see all of each other's Logs, including Details and past history. On a Friend's Log you
can leave a Reaction or a Comment that only you and the Log's owner can see. Every Monday morning
you get a Summary for last week (counts, daily average and change, most common Bristol type and
Awards), in the app and, by default, as a push notification. Other pushes (Friend requests,
Reactions/Comments on your Logs, a Friend logging) exist but start off.

Sign-in uses a passkey (Face ID) with a password as a backup. You can delete your Profile at any
time, which removes everything you made.

## User Stories

### Joining and signing in

1. As a Profile, I want to create an Invite link, so that a friend without a Profile can join.
2. As a Profile, I want to see my unused Invites with their expiry, so that I know which links are still live.
3. As a Profile, I want to revoke an unused Invite, so that a link I sent to the wrong person stops working.
4. As a Profile, I want to be stopped from having more than 3 unused Invites, so that links don't spread out of control.
5. As a newcomer, I want to open an Invite link and create a Profile with a Display name, an Avatar, and a password, so that I can start logging.
6. As a newcomer, I want an expired, revoked or used Invite to show a clear message, so that I know to ask for a new one.
7. As a newcomer, I want to be told that joining doesn't make me Friends with the inviter, so that I know to swap Friend codes.
8. As a visitor without an Invite, I want the sign-in page to say Throne is invite-only, so that I'm not confused by a missing sign-up form.
9. As a Profile, I want to add a passkey after sign-up, so that I can sign in with Face ID.
10. As a Profile, I want to sign in with a password if my passkey isn't available, so that I'm never locked out.
11. As a Profile, I want to stay signed in on my phone for days, so that logging is still one tap.
12. As a Profile, I want to sign out, so that I can hand my phone to someone.

### Profile

13. As a Profile, I want to change my Display name, so that Friends see what I want to be called.
14. As a Profile, I want to pick an Avatar emoji and color, so that Friends can spot me on the combined grid.
15. As a Profile, I want my Home zone to follow my device's time zone automatically, so that I never have to set it.
16. As a Profile, I want to see and override my Home zone, so that I can fix it if the device is wrong.
17. As a Profile, I want to delete my Profile after a clear confirmation, so that all my private data is gone for good.
18. As a Profile, I want deleting my Profile to end all my Friendships and remove the Reactions and Comments I left, so that nothing of mine remains.

### Logging

19. As a Profile, I want one big Log button on the home screen, so that logging takes one tap.
20. As a Profile, I want a Log to save at the current time in my Home zone, so that I don't have to enter anything.
21. As a Profile, I want instant confirmation (with an undo for a few seconds), so that I know it worked and can fix an accidental tap.
22. As a Profile, I want logging to work offline and sync later, so that bad bathroom signal doesn't matter.
23. As a Profile, I want to see which Logs are still waiting to sync, so that I know they haven't been lost.
24. As a Profile, I want a "details" expander on the new Log, so that I can add Details without slowing down the one-tap path.
25. As a Profile, I want to set the Duration in minutes, so that I can track how long I took.
26. As a Profile, I want to pick a Bristol type from 1 to 7 with simple icons and short labels, so that I don't need to remember the scale.
27. As a Profile, I want to add a short Note, so that I can remember context.
28. As a Profile, I want to toggle Flags (urgent, pain, blood, constipated, diarrhea), so that I can mark something worth noticing.
29. As a Profile, I want to change a Log's time up to 7 days back, so that I can record one I forgot.
30. As a Profile, I want future times to be refused, so that the calendar stays honest.
31. As a Profile, I want to edit the Details and time of my own Log later (within the same 7-day window), so that I can correct mistakes.
32. As a Profile, I want to delete my own Log, so that a wrong Log disappears for me and my Friends.
33. As a Profile, I want a Log to keep the Day it was logged on even after I travel, so that my past calendar never shifts.
34. As a Profile, I want an offline Log older than 7 days at sync time to be refused with a clear message, so that the rule is the same online and off.

### Calendar

35. As a Profile, I want a monthly Calendar of my own Logs, so that I can see my pattern at a glance.
36. As a Profile, I want each Day to show its count and get darker as the count rises, so that busy Days stand out.
37. As a Profile, I want Days with no Logs to stay blank, so that the grid is easy to read.
38. As a Profile, I want to move between months, so that I can look back.
39. As a Profile, I want today highlighted, so that I can find my place.
40. As a Profile, I want to tap a Day and see its Logs with times and Details, so that I can see what happened.
41. As a Profile, I want an Avatar row above the Calendar to switch between me and each Friend, so that I can look at one person at a time.
42. As a Profile, I want a combined grid where each Day shows a small count per person in their Avatar's color, so that I can compare everyone in one view.
43. As a Profile, I want Avatar colors that clash on the combined grid to be told apart, so that two Friends with the same color are still readable.
44. As a Profile, I want a Friend's Logs shown on their Days (their Log zone), so that their calendar matches what they see.
45. As a Profile, I want a monthly total and daily average under the Calendar, so that I get a quick number.
46. As a Profile, I want the Calendar to refresh when I open the app, so that I see Friends' new Logs.

### Friends

48. As a Profile, I want to regenerate my Friend code, so that an old code I shared too widely stops working.
49. As a Profile, I want to enter someone's Friend code and send a Friend request, so that we can become Friends.

55. As a Profile, I want to be stopped from sending a request to myself or to an existing Friend, so that nothing odd happens.
56. As a Profile, I want sending a request to someone who already sent me one to make us Friends, so that we don't both wait.

58. As a Profile, I want to see my Friends list with each one's Display name and Avatar, so that I know who sees my Logs.
59. As a Profile, I want to end a Friendship after a confirmation, so that someone stops seeing my Logs.
60. As a Profile, I want ending a Friendship to remove the Reactions and Comments each of us left on the other's Logs, so that nothing lingers.
61. As a Profile, I want a new Friend to see all my past Logs, so that their Calendar of me fills in right away.
62. As a Profile, I want people who aren't my Friends to never see my Logs, Display name or anything else of mine, so that it stays private.

### Reactions and Comments

63. As a Profile, I want to put one of 6 fixed emoji as a Reaction on a Friend's Log, so that I can respond quickly.
64. As a Profile, I want to change or remove my Reaction, so that I can fix a mis-tap.
65. As a Profile, I want only one Reaction per person per Log, so that it stays tidy.
66. As a Profile, I want to write a Comment of up to 200 characters on a Friend's Log, so that I can say something.
67. As a Profile, I want to delete my own Comment, so that I can take it back.
68. As a Log owner, I want to delete any Comment on my Log, so that I control my own Logs.
69. As a Log owner, I want to see all Reactions and Comments on my Logs, so that I know how Friends responded.
70. As a Friend, I want to see only my own Reactions and Comments on someone else's Log, so that people who aren't Friends with each other never see each other.
71. As a Profile, I want a Day with Reactions or Comments to show a small marker, so that I notice them.
72. As a Log owner, I want deleting a Log to delete its Reactions and Comments, so that nothing is left over.

### Summary and Awards

73. As a Profile, I want a Summary every Monday morning in my Home zone covering last Monday to Sunday, so that I get a weekly recap.
74. As a Profile, I want the Summary to show total Logs for me and each Friend, so that we can compare.
75. As a Profile, I want each person's daily average and the change from the week before, so that I can see trends.
76. As a Profile, I want each person's most common Bristol type (where they logged one), so that quality shows up too.
77. As a Profile, I want Awards (Most regular, Early bird, Night owl, Streak) given to whoever earned them, so that it's fun.
78. As a Profile, I want ties to share an Award and Awards to need enough data, so that one Log doesn't win a title.
79. As a Profile, I want the latest Summary as a card in the app and past Summaries in a list, so that I can look back.
80. As a Profile, I want the Summary to include only my current Friends, so that ex-Friends don't show up.
81. As a Profile with no Friends, I want a Summary of just myself, so that it's still useful.

### Notifications

82. As a Profile, I want a push for the weekly Summary, on by default, so that I don't miss it.
83. As a Profile, I want an optional push when I get a Friend request or one I sent is accepted, so that I can respond quickly.

89. As a Profile, I want pushes to never show Details on the lock screen, so that private information isn't exposed.

### App and safety

90. As a Profile, I want to install Throne to my home screen with its own icon, so that it opens like an app.
91. As a Profile, I want light and dark mode to follow my phone, so that it's easy on the eyes at night.

## Implementation Decisions

### Stack and layout

- Same stack and repo layout as HoneyDo and NutriSage: TypeScript npm workspaces `shared`, `api`, `web`,
  `infra`, plus a `schema` folder with the GraphQL schema split per entity. React + Vite PWA with a service
  worker; AppSync GraphQL API backed by one Lambda handler; one DynamoDB table (on-demand, PITR on);
  Cognito user pool; CDK stacks Cert (us-east-1), Api/Web (us-west-1) and Ci (GitHub OIDC deploy role
  that trusts only the `production` environment). Domain throne.ashershores.com in the shared
  ashershores.com hosted zone. `app=throne` cost tag and a $1/month budget.
- All pure logic (Day bucketing, heat levels, Summary math, Awards, Friend-code format, validation
  limits) lives in `shared` and is used by both the api and the web client.

### Identity and sign-up

- Cognito self sign-up is enabled but gated by a pre-sign-up trigger that requires a valid Invite
  token. The trigger first reads the Invite, then checks the username is free (AdminGetUser on this
  pool; a taken username is refused and leaves the Invite open), and only then marks the Invite used
  with a conditional write (an Invite can be spent only once; if a later Cognito step fails the Invite
  is burned and the inviter makes another). Unknown, expired, revoked or used tokens reject sign-up
  with a generic message.
- Invite: random 128-bit token; creator, created-at, expires-at (7 days), status (open/used/revoked).
  At most 3 open Invites per Profile, checked on create.
- On first sign-in the handler creates the Profile record (Display name 1–24 chars, Avatar emoji
  from a fixed list, Avatar color from a fixed palette of 8, Home zone as an IANA zone name), a Friend
  code, and default push preferences (Summary on, all others off).
- Passkeys plus password, Cognito refresh tokens 7 days, same as HoneyDo. Every API call identifies
  the caller by the Cognito `sub`; the client never sends a Profile ID for itself.

### Friend code and Friendship

- Friend code: 6 characters from an unambiguous alphabet (no 0/O/1/I/L), shown in two groups of 3
  (e.g. `4KQ-9XM`); stored as a unique lookup item (conditional put; retry on collision). Regenerating
  deletes the old lookup item, so the old code returns "not found".
- Friend request lookup returns the same "not found" for a bad code, yourself or an existing Friend
  (not a different error per case). Sending is capped at 10 per Profile per rolling day.
- Friendship is stored as a pair of items (one under each Profile) written in a single transaction,
  with both Profiles' Friend counts updated under a condition that each stays at or below 3. Accept
  re-checks both caps in the same transaction. A request from A to B while B has a pending request
  to A is accepted automatically.
- Ending a Friendship deletes both items and, in the same operation, every Reaction and Comment
  either Profile left on the other's Logs (batched; idempotent if retried). Past Summaries are kept
  as they were (they may still show the ex-Friend); only future Summaries leave them out.
- A real Friend code whose owner already has 3 Friends answers "They already have 3 Friends". This
  tells the sender the code is real, a deliberate trade-off against story 50's "same answer for every
  failure": the sender learns only that much, and the 10-a-day cap limits probing.
- At most 5 sent Friend requests wait at once ("Cancel one first"). A sent request is listed and
  cancelled by an opaque request id, never the receiver's Profile id (story 62).
- Friend, Friend request, Reaction and Comment actions are online only (not queued in the outbox);
  offline the app says so instead.

### Logs and Days

- Log: id (client-generated UUID so offline retries are idempotent), owner, instant (UTC), Log zone
  (IANA), Day (YYYY-MM-DD in the Log zone, computed server-side from instant + Log zone and stored),
  and optional Details: Duration (1–180 minutes), Bristol type (1–7), Note (up to 200 chars),
  Flags (subset of the fixed five).
- Time rules (server time): instant may not be more than 5 minutes in the future (clock skew), nor
  more than 7 days in the past at the moment the server receives it. Edits follow the same rule
  for the new time. Offline Logs that arrive too late are rejected with a specific error the
  outbox shows to the user.
- Key design: Logs sorted by owner then Day then instant so a month is one range query per Profile.
  The combined grid makes one query per visible Profile (at most 4).
- Authorization: reading another Profile's Logs, Profile or Summary requires a Friendship item
  between the caller and that Profile; otherwise the API returns the same error as "not found".
- Offline: reuse HoneyDo's outbox pattern (queued mutations in local storage, replayed in order
  on reconnect, pending marker in the UI).
- Record caps (like HoneyDo): e.g. at most 50 Logs per Profile per Day, protecting cost.

### Reactions and Comments

- Reaction: one per (Log, author), emoji from a fixed set of 6; put replaces. Comment: up to 200
  characters, at most 20 per author per Log (counted per author, so the cap never hints at others'
  Comments), author or Log owner may delete. Both may be created only by a current Friend of the
  Log's owner.
- Display names and Comments refuse control and hidden/invisible format characters (shared `text.ts`).
- Reads: the Log owner gets all Reactions/Comments on their Logs; a Friend reading someone else's
  Log gets only the ones they wrote. This filter is enforced in the handler, not the client.
- Deleting a Log deletes its Reactions and Comments.

### Summary and Awards

- A scheduled notifier Lambda runs hourly. For each Profile whose Home zone local time just passed
  Monday 08:00, it builds a Summary for the previous Monday–Sunday Days (each person's Logs counted
  by their own Day), stores it, and sends the push if the Profile has Summary push on.
- Summary contents per person (the recipient plus current Friends): total Logs, daily average,
  change versus the week before, most common Bristol type (if any Logs had one).
- Awards (computed in `shared` as a pure function over the group's Logs for the week):
  Most regular (smallest spread of daily counts, needs Logs on at least 5 Days), Early bird
  (earliest median local time of first Log per night), Night owl (latest median local time of last Log
  per night), Streak (longest run of consecutive Days with at least one Log, at least 3). Each Award needs
  at least 2 people with enough data; ties share the Award.
- Early bird and Night owl need Logs on 3+ nights. For these two only, a Log before 04:00 local (its
  Log zone) belongs to the night before, so 00:30 counts as late, not early; Calendar Days and the
  other numbers still split at midnight.
- Past Summaries are kept (small items) and listed newest first, at most 104 (two years).
- Delete Profile removes the person's row and Awards from other Profiles' stored Summaries (found via
  pointers in their own partition); an Award they shared stays with the others.

### Push

- Web Push with VAPID, reusing HoneyDo's subscription handling (endpoint allowlist, max 10
  devices per Profile, dead subscriptions pruned).
- Preferences per Profile: summary (default on), friendRequests, reactionsComments, and a list of
  Friend IDs for "Friend logged" (default empty). Ending a Friendship removes that Friend from the list.
- Event pushes (Friend request/accept, Reaction/Comment, Friend logged) are sent asynchronously
  after the write succeeds, so logging stays fast. Push text never includes Details; for example
  "Sam logged" or "Alex reacted to your Log".

### Calendar UI

- Heat levels: 0 blank, then 1, 2, 3, 4+ mapped to four shades of one accent color (same rule in
  light and dark). Combined grid: up to 4 small counts per Day in Avatar colors; if two visible
  Profiles share a color, the later one in the Friends list gets an alternate shade plus its emoji.
- Views: Me / each Friend (switcher) and Everyone (combined). Tap Day opens a sheet with that Day's
  Logs (time, Details, Reactions/Comments as allowed).
- Data refreshes on app open/focus and pull-to-refresh; no live subscriptions in v1.

### API security

- AppSync: Cognito user-pool auth only, introspection off, a query depth limit computed from the
  deepest real selection (test-guarded, see lessons from NutriSage), resolver-level input validation
  in the handler. CSP/headers as in HoneyDo. Every DynamoDB expression aliases attribute names.

## Testing Decisions

- Good tests check external behavior through the highest seam: what a Profile can do and see,
  never internal helpers or table layout.
- Seam 1 (main): the real Lambda handler called as any of several Profiles against the in-memory
  fake DynamoDB (HoneyDo's api testing harness pattern). Covers Invite create/revoke/cap, the
  pre-sign-up trigger, Profile creation, Friend code lookup/regenerate, Friend requests (cap,
  self, duplicate, mutual auto-accept, daily limit), Friendship end and its cleanup, Log
  create/edit/delete with the 7-day/future rules and idempotent retries, visibility (non-Friends
  get "not found"), Reaction/Comment privacy between Friends who aren't Friends with each other,
  cascade deletes, Profile deletion, push preference changes and Summary generation for a given time.
  The fake must enforce the same limits as the real services (conditional writes, transaction
  conditions, reserved words, query depth).
- Seam 2: pure functions in `shared`: Day from instant + zone (DST changes, date line, travel),
  heat level, Summary math (averages, change, most common Bristol type), Awards (thresholds, ties),
  Friend-code format, validation limits.
- Seam 3: browser e2e (Playwright) against the built bundle with a fake backend: one-tap Log and
  undo, details expander, offline outbox (go offline, log, reconnect, synced), Calendar switcher and
  combined grid, Day sheet, Friend request flow, push settings toggles, plus the screenshot tour
  (phone, desktop, dark) reviewed by eye.
- Prior art: HoneyDo `api/src/testing/harness.ts` + `fakeDynamo.ts`, HoneyDo/NutriSage `e2e/`
  (backend.ts, tour.ts), NutriSage schema parse and query-depth tests.

## Out of Scope

- Guest demo (/demo) and any public sample data.
- CSV or any data export.
- Photo avatars or any file uploads.
- Custom Flags, custom Reaction emoji.
- Handles, usernames, search or directories of Profiles.
- Groups larger than "you plus 3 Friends", or one-way sharing.
- Hiding individual Logs or Details from Friends (Friends see everything).
- Live updates via subscriptions.
- Daily Summaries, health insights, medical advice or alerts about Flags.
- Native apps; Android-specific polish.

## Further Notes

- This is sensitive personal health data. Keep it out of logs (no Notes or Details in CloudWatch),
  out of push text, and behind Friendship checks on every read.
- Defaults chosen without asking (change any): the 6 Reaction emoji; 200-character Comment
  and Note limits; Duration 1–180; Award thresholds above; 10 Friend requests/day; 50 Logs/Day cap;
  Summary at 08:00 local Monday.
- After v1 ships: add the App Connector Tile and portfolio card, then consider the guest demo
  (GUEST-DEMO-TODO.md).
